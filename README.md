# vibe-on-wheels

Вайб На Колесах - мобильное Flutter-приложение для совместных поездок.

Приложение поддерживает два сценария использования:

- Пассажир: ищет водителя и бронирует место.
- Водитель: публикует свою поездку и ожидает заявки.

## Быстрый старт

1. Установите Flutter SDK и Android Studio (или другой способ запуска Android/iOS эмулятора).
2. Проверьте окружение:

   ```bash
   flutter doctor
   ```

3. В корне проекта установите зависимости:

   ```bash
   flutter pub get
   ```

4. Запустите эмулятор/устройство и выполните:

   ```bash
   flutter run
   ```

## Тестовый вход

- Дефолтный аккаунт для входа: +7 999 123-45-67
- Регистрация новых пользователей доступна прямо в приложении (экран "Регистрация").

## Что уже реализовано

- Авторизация по номеру телефона и регистрация нового пользователя.
- Главный экран с картой и выбором сценария:
  - "Ищу водителя" (пассажир).
  - "Ищу попутчиков" (водитель).
- Поиск поездок с датой/временем, оплатой, местами и комментарием.
- Публикация поездки водителем с подтверждающим диалогом.
- Бронирование поездки пассажиром с подтверждающим диалогом.
- Симуляция решения водителя (через короткую задержку), перенос принятой поездки в "Мои поездки".
- Переход в чат с водителем после подтверждения поездки.
- Экран сообщений: список чатов, открытие диалога, отправка сообщений, имитация кнопки вложения фото.
- Профиль пользователя с динамическими счетчиками, историей поездок, отзывами и настройками.
- Редактирование профиля в настройках (имя, фамилия, телефон).
- Экран-онбординг по нижним вкладкам при первом входе в приложение.

## Основные пользовательские сценарии

### 1. Пассажир: поиск и бронирование

1. Вход в приложение.
2. На главном экране выбрать сценарий "Ищу водителя".
3. Указать адреса "Откуда" и "Куда" (или выбрать точки на карте).
4. Перейти к деталям, указать дату/время и параметры.
5. Выполнить поиск, открыть подходящую поездку.
6. Подтвердить отправку заявки на бронирование.
7. После симуляции подтверждения водителем поездка добавляется в "Мои поездки", а водитель - в "Сообщения".

### 2. Водитель: публикация предложения

1. На главном экране выбрать сценарий "Ищу попутчиков".
2. Заполнить маршрут и параметры поездки.
3. Подтвердить публикацию в диалоге.
4. Новая поездка добавляется в пул опубликованных предложений и участвует в поиске.

### 3. Профиль и настройки

1. Открыть вкладку "Профиль".
2. Перейти в "Настройки" и изменить имя/фамилию/телефон.
3. Сохранить изменения - они обновляют текущего пользователя в состоянии приложения.

## Как устроен поток данных в коде

### Поиск поездок

`HomeScreen/TripsScreen -> TripViewModel.fetchTrips() -> SearchTripsUseCase.execute() -> TripRepositoryImpl.findTrips() -> generateMockTrips()`

Дополнительно `TripViewModel` объединяет результаты с поездками, опубликованными пользователями в рантайме (`_publishedTrips`).

### Бронирование

`TripDetailsScreen -> TripViewModel.handleJoinRequest() -> JoinTripUseCase.execute() -> BookingRepositoryImpl.saveBooking() -> createMockBooking()`

После успешного бронирования включается таймер подтверждения водителя (имитация), затем:

- поездка переносится в персональную историю пользователя;
- водитель добавляется в список чатов пользователя.

### Публикация поездки водителем

`HomeScreen._submitDriverTrip() -> TripViewModel.publishDriverTripOffer()`

Создается локальная поездка и сохраняется в `_publishedTrips`, после чего становится видимой в результатах поиска.

### Авторизация и регистрация

- Вход: `AuthViewModel.login()` проверяет пользователя в `mockUsers`.
- Регистрация: `AuthViewModel.register()` создает нового `Passenger` и добавляет его в `mockUsers`.
- Обновление профиля: `AuthViewModel.updateCurrentUserProfile()` меняет имя/фамилию/телефон текущего пользователя с проверкой уникальности номера.

## Моковые данные и имитация бэкенда

Главный источник моков: `lib/data/mock_data.dart`

- `mockDrivers` - список водителей.
- `mockUsers` - пользователи для входа/регистрации.
- `generateMockTrips()` - генерация результатов поиска.
- `createMockBooking()` - создание мок-бронирования.

Имитируемая сеть реализована через `Future.delayed(...)` в репозиториях и view model.

## API и интеграции

### 1. OpenStreetMap Tiles (внешний API)

- Используется в `HomeScreen` через `flutter_map`.
- Источник тайлов: `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`.
- Карта показывает:
  - маркеры точки отправления и прибытия;
  - линию маршрута между выбранными точками.

### 2. Nominatim Geocoding API (внешний API)

Используется в `HomeScreen` (внутренний helper `_NominatimApi`).

- Прямой поиск адреса:
  - `GET https://nominatim.openstreetmap.org/search`
  - параметры: `q`, `format=json`, `limit=1`, `addressdetails=1`, `accept-language=ru`
- Обратный геокодинг по точке на карте:
  - `GET https://nominatim.openstreetmap.org/reverse`
  - параметры: `lat`, `lon`, `format=json`, `addressdetails=1`, `accept-language=ru`, `zoom=18`
- Особенности обработки:
  - ставится `User-Agent` в HTTP-запросе;
  - приоритет адресам с номером дома;
  - есть fallback на введенный пользователем адрес, если геокодер вернул менее точный.

### 3. Имитация backend API (внутренний контракт)

Реальные HTTP-вызовы к собственному backend пока не подключены, но в коде сохранен API-контракт:

- `POST /api/auth/login` - в `AuthViewModel.login()`.
- `GET /api/trips` - в `TripRepositoryImpl.findTrips()`.
- `GET /api/drivers/:id` - в `TripRepositoryImpl.getDriverById()`.
- `POST /api/bookings` - в `BookingRepositoryImpl.saveBooking()`.

Это упрощает дальнейший переход с моков на настоящий сервер: точки интеграции уже выделены в репозитории/use case/view model слои.

## Текущие ограничения

- Данные хранятся в памяти приложения и сбрасываются после перезапуска.
- В чатах нет серверной синхронизации и истории между сессиями.
- Кнопка вложения фото в чате пока работает как заглушка (имитация будущей функции).
- В `pubspec.yaml` добавлены `firebase_core` и `firebase_messaging`, но в текущем коде они еще не задействованы.
